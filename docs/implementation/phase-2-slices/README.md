# Phase 2 Slice Dossiers

Phase 2 converts Central from a single-agent runner into a durable multi-agent orchestration engine. These dossiers follow the `phase-1-slices/` precedent: each maps a GitHub issue (epic #90, design gate #91) onto packets, a slice-acceptance gate, and evidence artifacts. The nine Phase 2 specs under `docs/internal/superpowers/specs/` (dated 2026-10-07) define the vocabulary; the dossiers define the executable vertical slices.

## Dependency order — a → b → c → d → e → f

1. **Slice 2A — Workflow Graph and Lineage** (`slice-a-workflow-graph-lineage.md`, issue #92, packets P2A01–P2A06, gate `S2A-G1`): the append-only `workflow_node`/`dependency_edge` store, `central.child-spec/v1` batch validation and dynamic expansion, the node state machine with event-driven readiness and cancel cascade, the canonical event journal with reconstruction rules, and artifact lineage with the `central artifact read` sibling-data CLI. Foundation for everything after it. **S2A-G1: Accepted (machine tier, self-issued)** — manifest [`phase-2-slice-a-acceptance.json`](../../internal/superpowers/reviews/evidence/phase-2-slice-a-acceptance.json), verdict [`2026-10-08-s2a-g1-acceptance.md`](../../internal/superpowers/reviews/2026-10-08-s2a-g1-acceptance.md).
2. **Slice 2B — Scheduler and Workers** (`slice-b-scheduler-workers.md`, issue #93, packets P2B01–P2B06, gate `S2B-G1`): the `SELECT … FOR UPDATE SKIP LOCKED` ready queue and single-transaction atomic claim, dispatch with git-worktree/private-directory workspace provisioning, worker registration and capability matching, heartbeat renewal and lease fencing, the suspect/lost missed-beat ladder with reconcile-before-reinvoke, and concurrency admission with cap enforcement. **S2B-G1: Accepted (machine tier, self-issued)** — manifest [`phase-2-slice-b-acceptance.json`](../../internal/superpowers/reviews/evidence/phase-2-slice-b-acceptance.json), verdict [`2026-10-08-s2b-g1-acceptance.md`](../../internal/superpowers/reviews/2026-10-08-s2b-g1-acceptance.md).

Each slice depends on the prior slice's final packet; the acceptance suite is last because it consumes every other slice's failure semantics. Locked maintainer decisions (2026-10-07) are encoded throughout: leader-is-a-harness-session, append-only dynamically expanding graph, depth cap 3, worktree-vs-private workspace isolation, ambiguous attempts as operator decisions at every level, `central artifact read` sibling data flow, and session-granularity ceilings.
