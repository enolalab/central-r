Detailed outcomes, workstreams, required specifications, acceptance scenarios, non-goals, and exit criteria are defined in [`phases.md`](./phases.md). ## Phase 1 — Local Central MVP

Deliver a single-user local application with a Go kernel, protected bootstrap/session flow, server-rendered web UI, PostgreSQL, MinIO, basic task execution, logs, artifacts, cancel, retry, restart recovery, operator-driven local backup/restore, and reproducible minimum-profile acceptance benchmarks.

**Exit:** one workflow completes end-to-end, recovers after application restart and a verified local restore, and passes the complete Phase 1 compatibility, recovery, security, and performance/resource suite.

## Phase 2 — Durable multi-agent orchestration

Add parent-child task graphs, parallel subagents, dependencies, checkpoints, retry policy, timeout, backoff, idempotency, heartbeat, worker-loss recovery, event persistence, and artifact lineage.

**Exit:** interrupted workflows resume without losing completed durable work.

## Phase 3 — Extensibility platform

Add agent, tool, and model-provider SDKs; plugin manifests; MCP client integrations; sandboxing; permission boundaries; secrets management; and a developer CLI.

**Exit:** external developers can add agents and tools without modifying the kernel.

## Phase 4 — Central Server and Online Mode

Introduce a hosted control plane and outbound local connection with reconnection, session resume, command delivery, event streaming, offline buffering, and verified artifact transfer.

**Exit:** Local Central can be controlled remotely or participate as a local execution node.

## Phase 5 — Enterprise readiness

Add organizations, workspaces, RBAC, service accounts, SSO, audit logs, retention, quotas, policy, approval workflows, private deployment, observability, scheduled/remote backup automation, tested RPO/RTO, disaster recovery, and business-continuity controls. Phase 5 extends rather than owns the operator-driven single-node backup/restore required in Phase 1.

**Exit:** the product can support real enterprise pilots.

## Phase 6 — Ecosystem and scale

Add marketplaces, collaboration, evaluations, model routing, distributed scheduling, autoscaling, GPU scheduling, multi-region execution, public APIs, and usage billing.

**Exit:** Central operates as a broader platform.

## Delivery rule

Do not start cloud complexity before the local runtime demonstrates reliable task completion, crash recovery, and reproducible artifact and state persistence.
